# Разбор дефектов части A

В стартовом коде ДЗ 6 было четыре дефекта. Каждый тихо ломал воспроизводимость
или контроль качества. Явной ошибки ни один из них не давал.

## 1. Смешивание runs (`src/sweep.py`)

**Было.** Внутри родительского `sweep` открывался один вложенный run
`all-candidates`, и все шесть кандидатов писали в него. Параметры логировались
только при пустом `data.params` (`if not ...params`), поэтому r/lr/target_modules
оставались от первого кандидата. Метрики `val_loss` шести обучений сливались в
одну кривую, `model/` перезаписывался, теги `candidate` затирали друг друга.
Сравнивать было нечего: в MLflow виден один run со смешанной историей.

**Стало.** У каждого кандидата свой дочерний run
`mlflow.start_run(run_name=name, nested=True)` прямо под `sweep`. Параметры
логируются безусловно: повторная запись другого значения теперь падает и
не проходит молча. Итог: шесть отдельных FINISHED runs, у каждого свои params,
кривые, `samples.json` и модельный пакет (проверки 1, 3, 4 в `make check`).

## 2. Потеря артефактов (`compose.yaml`)

**Было.** MLflow писал артефакты в `/mlartifacts` внутри контейнера. Volume
`artifacts` был объявлен, но к сервису не подключён (`# TODO`). Postgres
сохранял метаданные runs, а файлы (адаптеры, MLmodel, samples) исчезали при
`--force-recreate` или `make down/up`. Реестр после этого ссылался на пустоту.

**Стало.** `volumes: - artifacts:/mlartifacts` у сервиса `mlflow`. Проверка
`make check-storage` пересоздаёт контейнер и сверяет SHA256 артефакта: PASS.

## 3. Нет версии данных (`src/sweep.py`)

**Было.** `versions = {k: v for k, v in provenance(p).items() if not k.startswith("data_")}`:
`data_train_sha256` и `data_val_sha256` выкидывались из тегов. `select()`
в `promote.py` требует эти теги, поэтому либо всё падало, либо (после «починки»
проверки) runs на разных тензорах считались сопоставимыми.

**Стало.** В теги родителя и каждого кандидата пишется полный `provenance(p)`:
git sha, dirty-флаг, sha кода, конфига, train.pt и val.pt. Проверка 2 PASS.

## 4. Обход порога по loss (`src/promote.py`)

**Было.** `promote()` считал `ratio`, сразу вызывал `register_model` и ставил
тег `validation=passed` и alias. Функция `gate()` с проверкой порога
`max_val_ratio`, конечности метрик и статуса run существовала, но не вызывалась.
Любой кандидат, даже хуже базы, попадал в реестр как «проверенный».

**Стало.** `ratio = gate(run, threshold)` стоит до любой записи в реестр.
При отказе версия не создаётся. Проверка 6 (`порог 0.0` → отказ без регистрации) PASS.

## Попутно найдено при сдаче части B

- Строгий scorer показал, что Qwen3-0.6B ставит точку после JSON (`{"answer":"B"}.`).
  Это не дефект кода, а реальная ошибка формата модели; разбор в `conclusion.md`.
- `git_dirty=True` в runs: в общем репозитории есть незакоммиченные изменения
  в соседнем каталоге `hw5-broken/`. Код ДЗ 6+7 закоммичен, `code_sha256` совпадает.
