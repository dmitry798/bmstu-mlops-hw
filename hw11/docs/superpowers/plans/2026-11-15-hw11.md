**Goal:** Complete every requirement of homework11.html on a real local Kubernetes cluster, then record a silent OBS screen demonstration.
**Architecture:** Continue HW8–10's FastAPI/backend/artifact contract. Add an explicit simulated CPU streaming backend, a Helm deployment, in-cluster clients and Prometheus/Grafana; measure real requests and Kubernetes state.
**Tech stack:** kind v0.30.0, Kubernetes v1.34.0, Helm v3.19.0, Python/FastAPI, metrics-server, Prometheus, Grafana.
**Spec:** ../../homework11.html (authoritative).

## Constraints and choices
- No push and no deletion of existing user files. Preserve previous homework sources.
- Initial disk free: about 3.2 GiB. Keep host tools/images bounded; put kind's writable containerd store in a dedicated 8 GiB tmpfs Docker volume. Node <=8 GiB RAM/6 CPUs. Check free disk before each image operation; stop rather than fill disk.
- One control-plane node, two API replicas, four distinct client Pod IPs; regular and ClientIP Services select exactly the same API Pods.
- Uniform and 80%-single-client schedules reused exactly. 3 repetitions × >=120 s per compared combination. Fixed routing disables ClientIP affinity, repeats the same schedules. No dropped runs.
- Backend explicitly simulated in every response, bounded prefix LRU, CPU work, warmup, queue, concurrency and chunks. No fake tokens/TTFT claims.
- ConfigMap artifact per version, verified SHA; external request-carried dialogue. Metrics never label request/session IDs.
- Prometheus retention <=2 h / 256 MiB, bounded emptyDir volumes. A single bounded writer for result files; no suppressed errors or fabricated PASS.
- User has authorized completion and recording; execute inline and make routine implementation choices here. Clarify only absent lecture-company reference.

## Review focus
- Cancellation after 200 headers is an aborted stream, never a success; distinguish deadlines, rejected requests, unsent scheduled events and network errors.
- Probe startup gating vs backend readiness; endpoint propagation and draining must not cut a healthy rollout stream.
- Four client IPs and new TCP connections: host port-forward must not stand in for Kubernetes ClientIP routing.
- HPA uses average CPU / actual requests; new replicas do not invalidate ClientIP entries. CPU must be real computation.
- Percentiles must aggregate classic histogram buckets retaining le and include the same completed responses as client data; no request/session labels.
